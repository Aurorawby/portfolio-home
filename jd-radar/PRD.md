# JD 雷达 · PRD

## 1. 背景与问题

求职 AI 产品岗时，最常见的信息差是：**不知道市场到底在要什么能力**。

- 招聘 JD 看 20 份，还是只记得"要会 AI、要懂产品"；
- 简历和项目按自己的理解准备，投出去石沉大海，不知道 gap 在哪；
- 面试被问"你觉得自己和我们岗位的匹配度"，只能答"我学习能力强"。

现有做法（手动整理 Excel、找学长问、看面经）都靠人肉，而且不可复现。

## 2. 目标用户

| 用户 | 场景 |
|---|---|
| 求职/转岗 AI 产品的人（主用户） | 投递前扫描 10 份目标岗位，确定简历和面试重点 |
| 产品团队 / 招聘方（次用户） | 快速对齐一个岗位的能力要求，写 JD 或面试题 |
| 学生 / 训练营 | 对照岗位需求规划学习路线 |

## 3. 目标与非目标

**目标**

1. 粘贴 3-10 份 JD，30 秒内给出：市场高频能力、能力雷达、gap 清单；
2. 完全离线、不调模型、不上传内容（隐私是卖点）；
3. 结论可导出（Markdown），能贴进复盘笔记 / 简历准备文档。

**非目标**

- 不做简历解析、不做自动投递；
- 不做"匹配度百分比"这种伪精确指标（会误导）；
- 不替代真实面试判断。

## 4. 方案

**输入**：JD 文本（`---` 分隔）。

**处理**：
1. 文本归一化（全角转半角、小写、去空白）；
2. 用 **72 项能力词典**（6 组：产品洞察 / 数据与实验 / AI 与技术 / 交付与工程 / 协作与影响 / 商业化与行业）做词面匹配，每项含 3-8 个同义词；
3. 汇总：每项能力"被几份 JD 提到"、总词频；
4. 雷达图：6 组各自"有多少比例的 JD 提到了本组能力"；
5. 未识别词：把没进词典的高频 2-gram 列出来（提示词典缺口，而不是假装覆盖全）。

**输出**：
- 能力雷达（Canvas 绘制，无第三方库）；
- 高频能力 Top 15（带"几份 JD / 出现几次"）；
- "我有证据"勾选（localStorage 保存）→ gap 清单（按被提及 JD 数排序）+ 补齐动作；
- 一键导出 Markdown。

## 5. 指标设计

| 层级 | 指标 | 定义 |
|---|---|---|
| 质量 | 核心能力召回率 | 人工标注的核心能力中，被词典命中的比例（评测见 `eval/jd-radar/REPORT.md`：**92.7%**） |
| 质量 | Top-5 召回率 | 雷达前 5 项覆盖核心能力的比例（**94.0%**） |
| 质量 | 命中密度 | 平均每份 JD 命中项数（**13.6 项/份**，过高说明词典太宽） |
| 使用 | 一次扫描耗时 | 目标 < 1 秒（纯前端，实际毫秒级） |
| 使用 | gap 清单导出率 | 导出/分析次数（验证"结论可带走"） |
| 覆盖 | 未识别词占比 | 词典缺口预警，持续补词 |

**明确不做的指标**：不给"你的匹配度 87%"这类数字——词典命中率不等于竞争力。

## 6. 关键取舍

| 取舍 | 选择 | 理由 |
|---|---|---|
| 模型 vs 词典 | **词典**（纯前端） | 隐私、零成本、结果可复现；LLM 可以做增强版但不是 MVP |
| 精确率 vs 召回 | **优先召回** | 求职场景"宁可多列几条让我自己判断"，漏掉关键能力更致命；精确率靠人工筛 |
| 匹配度百分比 vs gap 清单 | **gap 清单** | 百分比是伪精确，清单能直接指导行动 |
| 72 项够不够 | 先 72 项 + 未识别词提醒 | 自定义词典后续开放；先把闭环跑通 |

## 7. 风险与边界

- 词典覆盖不了新词（已用"未识别高频词"提醒，不隐藏）；
- 同义表达识别弱（"用户视角"不一定命中"用户研究"）；
- JD 本身可能夸大或模板化，分析结果只反映"文本要求"；
- 不做精确率标注，不能宣称"识别准确率"。

## 8. 下一步

- 扩到 30 份 JD + 2 人交叉标注，补精确率；
- 区分「硬性要求 / 加分项 / 职责描述」的权重；
- 开放自定义词典（用户补词后本地生效）；
- 与面试复盘器打通：gap 能力 → 自动生成面试练习题。
