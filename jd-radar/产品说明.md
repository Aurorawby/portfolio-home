# JD 雷达 · 产品说明（作品集版）

> 一句话：**粘贴几份 JD，30 秒看清市场要什么能力、我差在哪。** 纯前端、不调模型、不采集数据。

---

## 1. 为什么做

求职 AI 产品岗时，我最大的焦虑不是"不会做"，而是**不知道市场到底要什么**：

- 看 20 份 JD，脑子里只剩"要会 AI、要懂产品"这种正确的废话；
- 简历按自己的理解写，投出去没回音，也不知道 gap 在哪；
- 面试被问"你觉得匹配度如何"，只能回答"我学习能力强"。

市面上的工具要么是招聘平台（只能看单份 JD），要么是付费测评（黑盒、还给你一个"匹配度 87%"）。
**没有一个工具能让我用自己的话，把市场要求变成一张能行动的清单。**

## 2. 我做成了什么

| 输入 | 处理 | 输出 |
|---|---|---|
| 3-10 份 JD 文本 | 72 项能力词典（6 组）词面匹配 + 归一化 | 能力雷达图 + 高频能力 Top 15 + gap 清单 + 未识别词提醒 |
| 勾选「我有证据」 | localStorage 保存，计算已具备/缺口 | 按"被几份 JD 提到"排序的补齐清单 + 可讲的优势清单 |
| 点击导出 | 生成 Markdown | 直接贴进复盘笔记 / 简历准备文档 |

**技术选择**：全程浏览器端（HTML + Canvas + localStorage），零后端、零 API、零成本。
理由是：求职数据很敏感，用户不该为了看一份分析就把 JD 上传到某个服务器。

## 3. 评测证据（可复现）

| 指标 | 数值 |
|---|---|
| 核心能力召回率 | **92.7%**（人工标注 10 份 JD 的核心能力） |
| Top-5 召回率 | **94.0%**（雷达排序前 5 覆盖核心能力的比例） |
| 命中密度 | 13.6 项/份（与人工标注数量接近，说明词典没宽到离谱） |

复现：`node eval/jd-radar/run.mjs`（报告：`eval/jd-radar/REPORT.md`）。

**没做的**：精确率标注（词典是候选信号，逐条判断 150+ 候选成本高）。所以**不宣称"识别准确率"**，
只报告召回和密度——这也是我在这份作品集里一直坚持的原则：**能证明多少说多少**。

## 4. 关键取舍

1. **词典而不是模型**：可复现、隐私、零成本；LLM 适合做"补充同义词"的增强版，不该是 MVP；
2. **不给匹配度百分比**：伪精确会误导，"gap 清单"才能指导行动；
3. **优先召回**：求职场景宁可多列几条自己筛，也不能漏掉关键能力；
4. **未识别词公开**：词典漏了就列出来，不假装覆盖全。

## 5. 边界

- 词典是人工写的 72 项，新词覆盖不到；
- 同义表达识别弱（"用户视角"未必命中"用户研究"）；
- JD 文本可能模板化/夸大，结果只反映"文本要求"；
- 不能替代真实面试和人工判断。

## 6. 如果继续做

- 扩到 30 份 JD + 2 人交叉标注，补精确率；
- 区分「硬性要求 / 加分项 / 职责描述」权重；
- 开放自定义词典（用户补词本地生效）；
- 与面试复盘器打通：gap 能力自动生成面试练习题。
