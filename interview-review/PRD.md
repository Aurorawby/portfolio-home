## 1. 背景与问题

求职季每场面试都是稀缺样本，但复盘率极低：面经散落在群聊和记忆里，"问了什么、我怎么答的、哪里崩了"事后对不上号；面试前想练，也凑不出一份自己的高频题库。**不复盘的面试等于白面。**

## 2. 目标与指标

**目标**：单场面试的复盘时间 ≤5 分钟，且产出可沉淀、可重练的题库笔记。

| 指标 | v1.0 验收线 |
|---|---|
| 题目提取准确率 | 一问一答式面经 ≥90%（漏题 ≤1 题/场） |
| 复盘动作完成率 | 卡片内「自评」填写率（产品自身无法统计，以导出笔记行为作代理） |
| 隐私 | 面经内容默认不出本机（0 上传） |

## 3. 用户与场景

| 用户 | 场景 | 用户故事 |
|---|---|---|
| 求职者（核心） | 面试当天复盘 | 作为求职者，我想粘贴面经就得到分类题库，这样当场记录不完整也不怕 |
| 求职者 | 下场面试前 | 作为求职者，我想按薄弱清单重练，这样同样的坑不踩第二次 |
| 帮同学改简历的人 | 收集多份面经 | 作为收集者，我想把几场面经合并归类，这样能总结出高频考点 |

## 4. 本期范围（v1.0 做了什么 / 不做什么）

**做**：规则层题目提取与分类（离线）、逐题卡片（考察点/回答要点/1-5 星自评）、薄弱题汇总、AI 增强（BYOK 可选）、localStorage 自动保存、导出 Markdown、打印。

**不做（及理由）**：
- ❌ 账号与云端同步——面经是敏感个人信息，默认不上传是底线，也是产品差异点；
- ❌ AI 生成"标准答案"——面试答案要用自己的话，给框架不给答案；
- ❌ 题库社区/分享——涉及他人隐私与版权，v1 不碰。

## 5. 功能需求与验收标准

### F1 题目提取（P0，已上线，纯离线）

- F1.1 输入面经文本，提取疑问句为题目：支持编号/「Q1」/「问题N」/「面试官：」前缀清洗；长行按句切分；去重；上限 50 题。
  **验收**：示例面经（12 行）提取 12 题，无遗漏、无重复、无候选人自述混入。
- F1.2 分类为 8 类题型：经历深挖 / 行为面 / 情景模拟 / 产品方法 / AI 认知 / 动机匹配 / 反问环节 / 开放问题（关键词启发式）。
  **验收**：示例面经 12 题覆盖 7 类；分类明显错误的可在 UI 单题层面容忍（v1 不做人工改类型，开放问题兜底）。
- F1.3 不依赖网络：无 Key、断网全流程可用。
  **验收**：断网状态完成"粘贴 → 提取 → 自评 → 导出"全流程。

### F2 逐题复盘卡片（P0，已上线）

- F2.1 每题卡片含：题型徽章、考察点（可手填）、我的回答要点（多行输入）、1-5 星自评、删除。
- F2.2 自评 ≤2 星的卡片标红并计入"薄弱"。
  **验收**：给 1 题打 2 星后，统计区「薄弱（≤2 分）」+1，卡片描边变红；再点同一星取消评分，统计回落。
- F2.3 统计条实时更新：题目总数、类型数、平均自评、薄弱数、类型分布 chips。
  **验收**：任一操作（提取/删题/改评分）后 1 秒内统计更新。

### F3 AI 增强（P1，已上线，BYOK 可选）

- F3.1 选择服务商（智谱/DeepSeek/Moonshot/Ollama/自定义）+ Key（仅存本机），对已提取题目批量补齐：类型覆写、考察点、答题框架（3-5 条）、1 个可能追问；并输出全场高频考点与易露怯点。
  **验收**：返回 JSON 与本地题目按文本匹配合并，未命中的题保持原状不报错；Key 变更后重试可用。
- F3.2 AI 不可用/超时/返回格式错误时给出可行动的错误提示，规则层功能不受影响。
  **验收**：填错 Key 点增强 → 明确报错；取消后仍可正常导出。

### F4 数据与导出（P0，已上线）

- F4.1 状态自动存 localStorage（防抖 250ms），重开浏览器恢复。
  **验收**：录入题目与评分 → 关闭页面 → 重开，内容与评分完整恢复。
- F4.2 一键导出 Markdown 复盘笔记：概览（题数/类型分布/平均自评）+ 逐题（类型/考察点/要点/自评/框架/追问）+ 薄弱清单（复选框列表）。
  **验收**：导出文件可用任意 Markdown 阅读器打开，薄弱清单与页面一致。
- F4.3 打印/存 PDF（打印样式隐藏操作按钮）。

## 6. 关键流程

粘贴面经 → 提取题目（规则层，即时）→（可选）AI 增强 → 逐题写要点 + 自评 → 导出 Markdown 进个人笔记库。

## 7. 非功能需求

- **隐私**：默认 0 上传；AI 增强为用户显式动作，仅发送题目文本，Key 存本机；
- **成本**：规则层 0 成本；AI 层由用户 Key 承担（免费模型可用）；
- **交付**：单文件 HTML，双击即用，可挂任意静态托管。

## 8. 风险与开放问题

| 风险 | 应对 |
|---|---|
| 大段叙述体面经提取效果差 | 引导语明示"一问一答最准"；v1.1 考虑叙述体分段提示 |
| 分类启发式误判 | 兜底为「开放问题」；AI 增强可覆写类型 |
| localStorage 清理导致数据丢失 | 导出 Markdown 作为持久化手段（产品内提示） |

**开放问题**：多场面试合并去重时，同一题不同场的表现如何聚合（按场次保留 or 按题合并）需用户反馈后定。

## 9. 发布计划

- **M1（已发布）**：F1-F4；
- **M2**：多场合并与跨场高频统计、按 JD 匹配题库、模拟面试倒计时模式。

## 竞品分析（2026-11 补充）

> 口径：基于公开产品能力的定性对比，未做付费/深度评测。

| 替代方案 | 它强在哪 | 在我们场景里的不足 | 我们的差异 |
|---|---|---|---|
| 牛客 / 一亩三分地面经 | 面经量大、真实、有社区讨论 | 没有结构化复盘：题目、分类、自评、改进要自己整理 | 粘贴面经自动抽题分类，逐题自评并导出 |
| Notion / Obsidian 模板 | 自由、可长期沉淀 | 靠手填，题目提取和分类费时间 | 规则提取题目 + 结构化复盘卡片 |
| ChatGPT | 能总结面经、给建议 | 输出不稳定，没有可复现的评分和题目分类 | 规则层负责抽题/分类/自评，AI 只可选补考察点 |

**结论：** 面经多不等于会复盘；产品负责“把面经变成可练的题”，不替代真实面试。
