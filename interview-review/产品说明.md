# 面试复盘器 产品说明（作品集版）

> 痛点：面经散落在群聊、笔记和记忆里。面试完想复盘，发现「问了什么、答了什么、哪里崩了」根本对不上号；
> 面试前想练，也凑不出一份自己的高频题库。投递季每场面试都是稀缺样本，不复盘等于白面。

## 1. 一句话

**把面经文字变成结构化题库：自动提取题目 → 分类 → 逐题自评 → 导出复盘笔记。**

- **离线可用**：纯本地运行（单文件 HTML，无后端、无数据上传），题目提取和分类靠规则引擎；
- **AI 增强（可选）**：粘贴自己的 API Key，AI 补每道题的考察点、答题框架、可能的追问，并给全场的高频考点与易露怯点；
- **自带使用场景**：作者本人求职季的主力工具——每场面试当天复盘，导出 Markdown 进自己的笔记库。

## 2. 目标用户与场景

| 用户 | 场景 | 现有做法 | 用了之后 |
|---|---|---|---|
| 求职者（核心） | 面试当天复盘 / 面试前翻题库 | 脑子记 + 聊天记录翻 | 5 分钟结构化复盘，薄弱题清单自动沉淀 |
| 帮同学改简历的人 | 收集多份面经归类 | 手抄 Excel | 粘贴即出题库，按类型统计 |
| 面试官 / 内推人 | 整理自己的题库给候选人 | 发文档 | 出题 → 导出 Markdown 分发 |

## 3. 关键决策

| # | 决策 | 为什么 |
|---|---|---|
| 1 | 规则层完全离线，AI 只做增强 | 面经是敏感个人信息，默认不上传任何服务器是底线；AI 层 BYOK、直连服务商，Key 只存 localStorage |
| 2 | 题目提取用规则而不是"必须 AI" | 一场面试 10-15 题，规则（问号边界 + 疑问词 + 前缀清洗 + 去重）准确率够用；离线兜底让产品在没 Key 时也完整可用 |
| 3 | 分类用关键词启发式并允许 AI 覆写 | 类型体系按产品/PM 面试题型设计（经历深挖/行为面/情景模拟/产品方法/AI 认知/动机匹配/反问环节），是"可教学"的分类学 |
| 4 | 自评是 1-5 星单选，≤2 分标红 | 复盘的核心动作是「诚实打分」；薄弱题自动汇总成下一次面试前的重练清单 |
| 5 | 数据存 localStorage + 导出 Markdown | 不做账号体系；复盘笔记的终点是用户自己的笔记库，不是我们的数据库 |
| 6 | 单文件 HTML | 与 Quiz Factory 同一交付标准：双击即用、可挂任意静态托管 |

## 4. 指标（如果持续运营）

- 复盘率：导入面经的场次 / 实际参加场次（目标 >70%，复盘比刷题重要）；
- 薄弱题重练完成率：薄弱清单勾选率；
- AI 增强使用率：衡量"规则层不够用"的真实比例，反向指导规则引擎的迭代优先级。

## 5. 边界与下一步

- 规则提取对「一问一答」式面经最准；大段叙述体面经建议先简单分行；
- AI 增强质量取决于模型与 Key 额度，输出仅作参考，考察点应以真实面试反馈为准；
- Roadmap：多场面试合并去重（跨场高频题统计）、按 JD 匹配题库、模拟面试倒计时模式。
