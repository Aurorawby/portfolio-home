# 汇报一页纸 OnePager · PRD

> 版本 v1.0 ｜ 2026-11-03 ｜ 作者：Aurorawby（AI 结对编程）
> 一句话：**粘贴大纲 → 代码解析结构、诊断缺口 → 渲染排版好的一页汇报，浏览器打印即 PDF。AI 只润色，结构判断由规则完成。**

---

## 1. 背景与问题

学生和职场新人汇报的三块摩擦：

- **不会排**：内容有了，排版一小时起步；模板站要么花哨要么像 PPT 截图拼贴；
- **不会查**：一页纸写完没人告诉你「没数字」「没下一步」——而这两点恰是汇报被打回的高频原因；
- **AI 工具只管写不管结构**：生成器吐一堆正确的废话，没有「这页能不能一眼读完」的判断。

**机会**：一页纸汇报有稳定结构（板块 ≤5、要点 ≤30 字、有数字、有 Ask/Next）。结构判断是规则活，
排版是模板活——都可以由代码完成；AI 只做它擅长的润色和摘要。

## 2. 目标用户与场景

| 谁 | 场景 | 频率 |
|---|---|---|
| 实习生 / 应届生 | 周报升级成月度汇报、述职一页纸 | 每月 1-2 次 |
| 研究生 | 开题 / 阶段进展汇报（导师只要一页） | 每学期 |
| 我自己 | 求职作品集的进展同步 | 随手 |

## 3. 产品目标与指标

**北极星**：从「有内容」到「可打印的一页纸」≤ 3 分钟。
**正确性护栏（可测试）**：大纲解析（板块 / 要点 / 数字计数）与结构诊断触发与手工判定完全一致（回归评测）。
**信任指标**（M2）：AI 润色后数字保真率 100%（用户抽查）。

## 4. 需求清单

| 级别 | 需求 | 验收标准（可测试） |
|---|---|---|
| P0 | 大纲解析：# 标题 / - 要点 / 自由文本 → 结构化板块 | 解析结果（板块数 / 要点数 / 数字处数）与手工标注一致（回归评测） |
| P0 | 结构诊断：无数字 / 数字过少 / 板块过多 / 缺下一步 / 争取资源无 Ask / 要点过长 | 6 类诊断触发条件与规则一致；全过时给「体检通过」 |
| P0 | 一页纸渲染：3 种版式（经典纵列 / 双栏 / 横幅+KPI），数字自动高亮 | 同一份数据 3 版式可切换；数字 span 高亮正确 |
| P0 | 打印导出：浏览器打印只输出一页纸（@media print） | 打印预览仅含 .onepager 内容 |
| P1 | AI 润色：要点改写为汇报语言（≤30 字，保留数字） | 返回条数与原要点不一致时报错不回写；改写后可检查回写 |
| P1 | AI 执行摘要：3 句话 TL;DR 写入页面顶部 | 数字由人工核对（页面提示） |
| P1 | 演示大纲：含数字与「下一步」板块 | 装载即生成 + 诊断通过 |
| P2 | 自定义配色 / Logo | 等有真实使用反馈 |
| P2 | 多页模式（进展 + 风险两页） | 违背「一页纸」初心，谨慎评估 |

## 5. 明确不做（Not-doing）

- **不做在线协作 / 多人编辑**：单机打印工具，协作是文档平台的事；
- **不做「AI 保证通过」**：结构诊断是启发式规则，写明不是「保证老板点头」；
- **不做免费版式农场**：3 套克制版式，不加 50 套花哨模板——一页纸的美感来自留白和层级，不是装饰；
- **AI 不编数字**：润色 prompt 明确「保留所有数字、不编造新数字」，回写条数校验。

## 6. 关键设计决策

1. **结构诊断先于排版**：解析完立刻给诊断（没数字？没下一步？），把「一页纸方法论」做成产品功能而不是使用说明；
2. **打印即 PDF**：不做服务端 PDF 渲染（需要后端），`@media print` + 隐藏其余元素——零依赖拿到 95% 的效果；
3. **AI 回写有条数校验**：润色返回条数不一致直接报错不回写，防止 AI 静默吞掉要点；
4. **数字高亮由正则统一处理**：三版式共用 numify()，视觉焦点自动落在数字上。

## 7. 页面流程（低保真线框）

```
┌────────────────────────────────────────┐
│ ① [标题][汇报人][受众▾][目标▾]          │
│    大纲 textarea（# / - / 自由文本）     │
│    [🔨生成] [🧪演示] [✨AI润色] [🧾摘要]  │
├────────────────────────────────────────┤
│    诊断：⛔ 没有数字 / ⚠️ 缺下一步 / ✅   │
├────────────────────────────────────────┤
│ ② 版式：[经典][双栏][横幅+KPI]           │
│  ┌──────── 一页纸预览（A4 比例）──────┐  │
│  │ 标题 · 元信息                      │  │
│  │ TL;DR（橙块，AI 可写入）           │  │
│  │ ■ 板块一  - 要点(数字高亮)         │  │
│  │ ■ 板块二  - …                     │  │
│  └───────────────────────────────────┘  │
│    [🖨 打印/PDF] [📋 复制 HTML]          │
└────────────────────────────────────────┘
```

## 8. 风险与对策

| 风险 | 对策 |
|---|---|
| 诊断误报（有些汇报确实不需要数字） | 文案写「建议」语气；复盘类目标不查「下一步」；页面声明是启发式 |
| 打印分页错乱 | min-height 而非固定高度；声明「建议 Chrome/Edge」；一页纸内容超页属用户内容过多，诊断已提示 |
| AI 润色丢数字 / 吞条目 | prompt 约束 + 返回条数校验 + 用户抽查提示 |
| 浏览器兼容 | 用最基础的 CSS（flex/grid/print media），不碰打印高级特性 |

## 9. 里程碑

- **M1（已完成，本版本）**：P0 全部 + P1 全部 + 解析/诊断回归评测；
- **M2（有真实使用后）**：自定义配色、用户访谈（3 分钟北极星）、打印兼容性清单。

## 10. 本 PRD 的局限

- 诊断规则来自通用汇报方法论与个人实习经验，未经大规模验证；
- 解析器认 # 与【】两种标题、- • 和数字编号三种要点，更怪的格式会退化成自由文本（可接受）；
- 打印效果依赖浏览器渲染，Safari / Firefox 未逐一验证。

## 竞品分析（2026-11 补充）

> 口径：基于公开产品能力的定性对比，未做付费/深度评测。

| 替代方案 | 它强在哪 | 在我们场景里的不足 | 我们的差异 |
|---|---|---|---|
| Gamma / Canva / AI PPT | 模板漂亮、设计能力强 | 结构诊断弱，容易“排版很美但内容空” | 先诊断结构（数字/下一步/Ask）再做版式 |
| 幕布 / 飞书文档 | 大纲、协作、多端成熟 | 导出成“一页纸”要手工排版 | 一键打印/存 PDF，三种版式 |
| ChatGPT | 能写汇报、能润色 | 不保证结构完整，数字可能被改 | 结构由规则算，AI 润色可选且提示核对数字 |

**结论：** 不是“更好看的 PPT”，是“先保证汇报结构成立，再谈好看”。
