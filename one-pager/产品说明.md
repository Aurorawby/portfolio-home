# 汇报一页纸 · 产品说明（作品集版）

> 一句话：**粘贴大纲，代码解析结构、诊断缺口（没数字？没下一步？Ask 不具体？），渲染成排版好的一页汇报——浏览器打印即 PDF。AI 只润色，判断归规则。**

---

## 1. 为什么做

汇报内容好写，一页纸难排：模板站花哨、PPT 太重、AI 生成器吐正确的废话。
更关键的是没人告诉你**这页哪里不行**——没数字、没下一步、Ask 不具体，这三点就是汇报被打回的高频原因。

一页纸汇报有稳定的结构规则。**规则就该交给代码**：解析大纲 → 诊断缺口 → 渲染版式，AI 只做润色和摘要。

## 2. 我做成了什么

| 模块 | 实现 |
|---|---|
| 大纲解析 | `#` / `【】` 标题、`-` / `•` / 数字编号要点、自由文本兜底，输出板块 / 要点 / 数字计数 |
| 结构诊断 | 6 条启发式规则：无数字（⛔）、数字 <3（⚠️）、板块 >5、缺「下一步」、争取资源无具体 Ask、要点 >40 字 |
| 一页纸渲染 | 3 版式（经典纵列 / 双栏 / 横幅+KPI 自动抽取 Top3 数字）、数字正则高亮、A4 比例预览 |
| 打印导出 | `@media print` 只输出一页纸 → 打印即 PDF；另支持复制 HTML |
| AI（可选） | 润色要点（≤30 字、保留数字、条数校验不回写）+ 3 句话执行摘要写进页面 |
| 演示大纲 | 一键装载真实风格大纲，诊断 / 渲染 / 高亮立即生效 |

## 3. 验证（可复现）

`node eval/one-pager/run.mjs`（不调用模型、不依赖浏览器）：

| 检查 | 结果 |
|---|---|
| 大纲解析（板块数 / 要点数 / 数字计数） | 3 组用例与手工标注逐字段一致 |
| 诊断触发（无数字 / 缺下一步 / 争取资源无 Ask / 全部通过） | 4 组用例触发与手工判定一致 |

**诚实口径**：确定性回归测试，保证解析与诊断代码和手工判定一致、防改动出错；
诊断规则本身是启发式（写明「建议」语气），不是「保证汇报通过」。

## 4. 关键取舍

1. **诊断先于排版**：先告诉用户哪里不行，再给版式——把「一页纸方法论」做进产品而不是说明书；
2. **打印即 PDF**：`@media print` 拿到 95% 的效果，零后端依赖，符合「双击即用」的产品性格；
3. **AI 回写有条数校验**：润色返回条数不一致直接报错——宁可报错，不能静默吞掉用户要点；
4. **3 套克制版式而不是 50 套模板**：一页纸的美感来自留白与层级，不是装饰。

## 5. 边界

- 解析器认常见格式（# 标题、- 要点），更怪的写法退化成自由文本（功能不损失，只是没板块结构）；
- 诊断是启发式：有些汇报确实不需要数字，页面文案用「建议」语气；
- 打印排版以浏览器为准（建议 Chrome / Edge），Safari / Firefox 未逐一验证；
- 数据存 localStorage，清浏览器数据丢草稿。

## 6. 如果继续做

- 自定义配色 / 校名 Logo；
- 5 人使用访谈验证「3 分钟出可打印一页」；
- 打印兼容性清单（Safari / Firefox 逐个验）。
