# 内容工作台 · 产品说明（作品集版）

> 一句话：**把选题雷达 → 笔记工坊 → 发布串成闭环的编排层：周计划、发布漏斗、数据回流分析、周简报——样本不足时明确说"不下结论"。**

---

## 1. 为什么做

内容线的工具已经有了（选题雷达管生成、笔记工坊管起草），但**发布之后是一片空白**：
数据散在平台后台，从来没人把它和「选题类型」对起来。选题策略永远得不到验证——
做了 13 个产品之后我意识到，缺的不是又一个生成器，是**闭环的最后一米**。

求职线有先例：求职工作台把三个工具串成一条线。内容工作台照此模式编排，
并把「数据回流」做成一等公民。

## 2. 我做成了什么

| 模块 | 实现 |
|---|---|
| 选题导入 | 直接读选题雷达的本地选题池（tr_pool），去重排除已导入/已弃 |
| 流水线 | 计划 → 草稿 → 已发布 Kanban，卡片流转 |
| **数据回流** | 发布卡内置阅读/赞/藏/涨粉录入，按选题类型聚合平均阅读 |
| 周简报 | 规则引擎：漏斗五段 + 4 类警告 + 行动清单，确定性计算 |
| **统计素养约束** | 类型建议强制样本 ≥3，不足时输出「均值会被单篇运气主导，先补样本」 |
| AI 点评 | 基于简报客观数据的教练式点评（约束不编造数据） |
| 周报导出 | Markdown（漏斗/行动/类型表现/明细表） |

## 3. 验证（可复现）

`node eval/content-workbench/run.mjs`（不调用模型、不依赖浏览器）：

| 检查 | 结果 |
|---|---|
| 漏斗统计（5 段） | 与手工计算一致 |
| 类型聚合（平均阅读） | 一致 |
| 建议触发（空/样本不足/样本足够三态） | 一致 |
| 简报警告（缺草稿/缺数据/池空） | 一致 |

**诚实口径**：确定性回归测试，保证简报引擎与手算一致；演示数据中的阅读量为编造示例（页面已注明），
真实结论需要真实数据。

## 4. 关键取舍

1. **编排而非重写**：每个工具保持单一职责，工作台只做「读、汇总、写回」——单改一个工具不拖垮全局；
2. **回流是闭环的灵魂**：没有数据回流，选题类型永远无法验证——这是与「纯看板」的本质区别；
3. **样本 ≥3 硬门槛**：统计上不完美（3 依然很小），但比「单篇爆款就 all in」强一个量级——
   门槛本身是产品给用户的教育；
4. **简报引擎可测**：警告与建议是确定性规则，改之前有回归兜底。

## 5. 边界

- 需要选题雷达在同浏览器有数据（同源 localStorage）；没有则给双指引（去生成/看演示）；
- 阅读量手动填写，以平台后台为准；
- 类型标签来自选题雷达自标，粒度粗；
- 演示数据阅读量为编造（页面注明）。

## 6. 如果继续做

- 笔记工坊草稿握手（草稿状态自动点亮）；
- A/B 标题实验记录（同题两标题的数据对比）；
- 类型标签细化（从标题自动归类）。
