# 求职工作台 · 集成、经历深挖与经历库测试报告

工作台不是新工具，而是把四个工具串起来：它的质量取决于**跨工具数据流**、**经历深挖逻辑**与**故事库**是否正确。
所以这里没有"精度指标"，而是**确定性断言**。

## 测什么

| # | 断言 | 说明 |
|---|---|---|
| 1 | 能读取三个工具的数据 | `jd_last`（JD 雷达）、`mock_interview_state_v1`（模拟面试官）、`ir_state`（复盘器） |
| 2 | 档案章节完整 | 基本信息 / ① JD 扫描 / ② 预测面试题 / ③ 真实面试复盘 / 下一步行动 |
| 3 | 高频能力被写进档案 | 从 JD 雷达结果读取 Top 能力 |
| 4 | 简历深挖题被写进档案 | 从模拟面试官结果读取引用简历的题 |
| 5 | 真实复盘与薄弱题被统计 | 自评 ≤2 的题进入薄弱清单 |
| 6 | 预测题能带入复盘器 | 合并去重；不覆盖已有问题 |
| 7 | 经历深挖：5 问流程 | 第一问是背景；答题后推进到下一问 |
| 8 | 经历深挖：STAR + Markdown | 生成 S/T/A/R 与可下载 Markdown |
| 9 | 经历深挖：不编数字 | 没有结果数字时写入“待补”，不自动生成数字 |
| 10 | 经历深挖：弱动词识别 | “负责/参与/协助”等被标记并给改写建议 |
| 11 | 经历库：能力标签 | 从故事文本归类到用户研究/产品定义/数据分析/内容增长/AI 评测/项目推进 |
| 12 | 经历库：Markdown 导出 | 导出包含 30 秒版、STAR、追问、待补 |
| 13 | 经历库：JD 覆盖 | 规则匹配 JD 关键词，区分已覆盖与缺口 |

## 结果

全部 13 项断言通过。复现：

```bash
node eval/job-workbench/run.mjs
```

## 已知局限

1. 这是**数据流测试**，不是真实用户走查；三步流程是否顺畅要等 3 人试用（见 `user-test-3/`）。
2. localStorage 只在同一浏览器同源共享，换设备会丢——这是设计选择（求职数据留本机）。
3. "待分类"题型是占位，需要用户在复盘器里自己改。
