# 模拟面试官 · 生成质量评测

- 用例数：**8** 组（JD + 简历，人工标注核心能力）
- 评测方式：Node 沙箱直接调用页面里的 `generateQuestions`，不经过浏览器、不调用模型
- 题库：31 项能力，每项 1 道能力题 + 1 个追问

## 总体结果

| 指标 | 数值 | 说明 |
|---|---|---|
| 核心能力覆盖率 | **74.1%** | 人工标注的核心能力里，被岗位题覆盖的比例（43/58） |
| 简历引用率 | **100.0%** | 简历非空的用例中，生成了至少 1 道引用简历原句的深挖题（8/8） |
| 追问完整度 | **100.0%** | 每道题都带一个追问的比例 |
| 去重率 | **100.0%** | 生成题目中没有重复问法的比例 |
| 通用题齐全率 | **100.0%** | 同时包含自我介绍与反问环节的用例比例 |
| 平均题数 | **12.6 道** | 一套面试准备列表的长度 |

> 说明：这套评测只看「覆盖与完整度」，**不评价问题本身写得好不好**
> （那需要人工逐题打分）。所以这里不宣称"题库质量高"，只说明规则层跑得住。

## 已知局限

1. 规则层是"题库 + 关键词匹配"，不同 JD 措辞变了就可能漏掉能力（例如把"用户洞察"写成不命中用户研究）；
2. 题目是通用问法，个性化程度有限——所以产品里把 AI 改写做成可选项；
3. 只测了 8 组用例、单人标注，覆盖率是方向性指标；
4. 没有测"问题是否真正针对候选人"，这需要真实面试官评分。
