# 图文工作室 XhsStudio · PRD

> 版本 v1.0 ｜ 2026-11-06 ｜ 作者：Aurorawby（AI 结对编程）
> 一句话：**小红书图文的全流程生产线——5 种近期跑通的爆款形态 schema 化（人设 Bot / 必看合集 / 必入榜 / 图文总结 / 对比测评），AI 按形态生成封面、内页、正文、标签、评论区运营脚本与发布策略，规则层校验结构与违禁词，一键导出发布包。发布由人完成。**

---

## 1. 背景与问题

小红书图文创作有成熟但**未被工具化的形态学**：

- 「人设 Bot 帖」「养生必看」「必入榜 + 评论区整理链接」「图文总结卡」「A vs B 测评」是近期反复跑通的爆款结构，
  但每个形态的**结构约定**（封面字数、内页数量、评论区怎么运营）散落在创作者的经验里，没有 schema 化；
- 现有 AI 工具只生成正文——**封面文案、内页卡片、评论区脚本、发布策略全靠自己想**，而这恰恰是爆款的主体；
- 「直接让 AI 自己发布」是小红书明确禁止的（无发布 API，自动化操作违反用户协议）——
  所以工具的正确终点是**发布包 100% 就绪 + 人工粘贴发布**。

**机会**：把 5 种爆款形态做成 JSON schema + 提示词 + 发布 checklist 的**模板资产**；AI 按形态生成全脚本；
规则层校验结构完整性与违禁词。这是内容线从「工具」到「生产线」的深化。

## 2. 目标用户与场景

| 谁 | 场景 | 频率 |
|---|---|---|
| 小红书创作者 | 周末批量生产：选形态 → 生成 → 改 → 导出发布包 → 逐篇发布 | 每周 1-3 篇 |
| 内容运营 | 为账号矩阵快速产出不同形态的图文脚本 | 每周 |

## 3. 产品目标与指标

**北极星**：从「有主题」到「发布包就绪」≤ 5 分钟。
**正确性护栏（可测试）**：结构完整性校验（封面字数/内页数量与厚度/正文字数/标签数/评论区/发布策略/违禁词）与手工判定一致（确定性回归）。
**信任指标**：发布包被真实使用（用户实际发布并回流数据到内容工作台）。

## 4. 需求清单

| 级别 | 需求 | 验收标准（可测试） |
|---|---|---|
| P0 | 形态模板库：5 种爆款形态，每种含 schema（封面字数区间/内页数量与厚度/正文字数/标签数）+ 生成提示词 + 发布 checklist | 模板 schema 完整可见；切换形态生成结果遵循对应 schema |
| P0 | 脚本校验引擎：7 项结构检查 + 违禁词扫描（封面+内页+正文+评论区全文） | 完整性百分比与 issue 列表与手工判定一致（回归评测） |
| P0 | AI 全脚本生成：按形态 schema 输出 cover/pages/body/tags/comments/publish JSON | JSON 容错；生成后自动体检 |
| P0 | 脚本编辑台：封面/内页（增删页）/正文/标签全部可改，改完实时重体检 | 编辑即时反映到体检结果 |
| P0 | 发布包导出：Markdown（封面/内页/正文/标签/评论区/策略/体检结果/checklist） | 内容与页面一致 |
| P0 | 精写示例：bot 形态人工精写脚本，**必须通过自家体检（100%）** | 装载即 100% |
| P1 | 发布策略生成：建议时间 + 发布后互动动作 | 每次生成都含 publish 字段 |
| P2 | 公众号形态扩展（深度长文结构） | 依赖 mp-formatter 排版联动，M2 |
| P2 | 内页图样式模板（文案 → 图片排版建议） | 需要图片生成，M2 评估 |
| **Not-doing** | **自动发布 / 平台数据抓取** | **小红书无发布 API，自动化违反用户协议——明确不做，页面常驻声明** |

## 5. 明确不做（Not-doing）

- **不做自动发布**：平台规则红线，工具终点是「发布包」，发布由人完成（页面常驻红标声明）；
- **不做热点抓取**：不抓平台数据；形态库沉淀的是「结构」而非「时效」——结构不会过时；
- **AI 不编造事实**：checklist 强制「内容事实已人工核对」；健康/法律类内容生成提示内嵌免责要求；
- **违禁词不做绕过建议**：给合规改法（同笔记工坊口径）。

## 6. 关键设计决策

1. **形态 schema 化是核心资产**：每种爆款形态 = 封面字数区间 + 内页数量/厚度 + 正文区间 + 标签数 +
   生成提示词 + 发布 checklist——把创作者隐性经验变成显式、可评测、可复用的结构；
2. **评论区脚本是生成的一部分**：爆款的一半在评论区（扣 1 / 补链接 / 预埋神评）——
   这是从「内容工具」到「运营工具」的分界线，也是市面工具的空白；
3. **示例必须过自家体检**：精写示例装载即 100% 完整性——自己 produce 的内容自己体检不过，工具就没有公信力；
4. **发布红线常驻页面**：不做自动发布以红 pill 形式常驻顶栏，PRD Not-doing 第一条。

## 7. 页面流程（低保真线框）

```
┌────────────────────────────────────────────┐
│ ① 形态卡 ×5（Bot/必看/必入榜/总结/对比）      │
├────────────────────────────────────────────┤
│ ② [主题][人群][人设]  [🤖生成] [🧪示例]      │
├────────────────────────────────────────────┤
│ ③ 脚本编辑台：封面 textarea                 │
│    内页卡片 ×N（标题+逐行要点，可增删）       │
│    正文 textarea ｜ 标签 ｜ 评论区脚本        │
│    发布策略卡                               │
├────────────────────────────────────────────┤
│ ④ 体检：完整性 100%（7/7）✅ 违禁词 ✅       │
│    发布前 checklist（人工逐项勾）            │
│    [📋导出发布包]                           │
└────────────────────────────────────────────┘
```

## 8. 风险与对策

| 风险 | 对策 |
|---|---|
| AI 生成偏离形态 schema | 生成后自动体检 + 编辑台实时重体检；JSON 容错 |
| AI 编造事实（假案例/假数据） | checklist 强制人工核对项；健康/法律类提示内嵌免责 |
| 违禁词漏检（词典边界） | 同笔记工坊口径；体检通过 ≠ 平台不判违规，页面明示 |
| 形态模板本身过时 | 模板是「结构」沉淀（比时效稳健）；每季度按真实爆款复盘更新 |
| 自动化发布的合规诱惑 | 产品红线常驻声明；PRD Not-doing 首条 |

## 9. 里程碑

- **M1（已完成，本版本）**：形态库 ×5 + 生成管线 + 校验引擎 + 编辑台 + 发布包导出 + 回归评测；
- **M2**：公众号深度形态扩展、内页图排版建议、生成结果的发布回流分析（与内容工作台联动）。

## 10. 本 PRD 的局限

- 5 种形态是对近期爆款的归纳，不构成「必爆」——结构是下限不是保证；
- 违禁词词典覆盖常见风险词但不完整；
- 「评论区预埋」涉及自评互动的灰色地带，已定位为「运营脚本建议」由用户自行判断尺度；
- 单人归纳的形态 schema，无第二人交叉验证。

## 竞品分析（2026-11-06 补充）

> 口径：基于公开产品能力的定性对比，未做付费/深度评测。

| 替代方案 | 它强在哪 | 在我们场景里的不足 | 我们的差异 |
|---|---|---|---|
| 小红书创作中心 | 发布、数据、站内灵感 | 不给你「爆款形态」的结构和可校验脚本，也不做违禁词体检 | 5 种形态 schema 化 + 生成 + 校验 + 发布包 |
| 稿定设计 / Canva | 封面/内页模板漂亮 | 只解决视觉，不解决正文/评论区/发布策略 | 封面+内页+正文+评论区脚本+发布策略一体 |
| 新红 / 零克查词 | 数据/违禁词查询成熟 | 查完还要自己写，生成与校验分离 | 生成后自动过校验，红线常驻 |

**结论：** 不是「AI 帮你发小红书」，是「把爆款形态变成可校验的脚本」；不自动发布、不抓平台数据。
