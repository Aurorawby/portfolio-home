# 选题雷达 · 产品说明（作品集版）

> 一句话：**AI 按你的账号定位一次生成 12 个候选选题，规则引擎给每个标题 6 维打分并说清「缺什么」——生成归 AI，判断归代码。**

---

## 1. 为什么做

我做过两年内容运营（头部社交平台 / 教育科技公司），「选题靠拍脑袋」是我和同事每周真实在发生的事：
刷一晚上同行号，存了 20 条链接，最后还是写了个平庸的。

市面上的方案各有缺陷：爆款标题生成器直接吐标题不解释原因；直接问大模型，一次给 20 条平均水平的，
没有筛选标准反而更累。**把「生成」和「判断」拆开**——AI 发散，规则收敛，人只做最后判断——
这是我作为运营 + 准产品经理能给出的解法。

## 2. 我做成了什么

| 模块 | 实现 |
|---|---|
| 标题打分器 | 6 维规则引擎（数字具体 / 身份代入 / 情绪唤起 / 反差悬念 / 时效钩子 / 长度健康），加权 0-100 分 + 每维「怎么补」的诊断建议，**纯离线** |
| AI 生成 | BYOK 一次生成 12 个候选，每条带「为什么能爆 / 同类规律 / 风险提醒」；支持智谱（免费档）/ DeepSeek / Moonshot / 本地 Ollama / 自定义 |
| 选题池 | 状态流转（待写→在写→已发→弃）+ localStorage 持久化 + 总分降序 |
| 看板 | 结构类型分布 + 状态漏斗 + 已发率（选题池自己的 BI） |
| 导出 | 一键复制 / 下载 Markdown 周选题表 |
| 演示模式 | 无 Key 装载 8 条人工精写选题，走完全流程 |

**关键架构**：AI 只产出文本候选，**分数全部由代码现算**——模型不能给自己的产出打分；
诊断文案告诉用户「缺什么、怎么补」，而不是给一个黑盒百分比。

## 3. 评测证据（可复现）

`node eval/topic-radar/run.mjs`（不调用模型），16 条人工标注用例（good 8 / weak 8）：

| 指标 | 数值 |
|---|---|
| 高分命中率（good ≥ 35 分） | **100%**（8/8） |
| 低分命中率（weak < 35 分） | **100%**（8/8） |
| 区分度（good 均分 58.4 − weak 均分 17.9） | **40.5 分** |
| 演示数据一致性 | 8/8 全部 ≥ 阈值 |

评测过程真实抓到并修掉一个缺陷：单字词「错」在词典里误命中「天气不错」，导致弱标题「今天天气不错，出来走走」
被误判 36 分——改为「踩坑」后该条降到 33 分，且不影响任何 good 用例（修复记录见 git 历史）。

**没做的**：流量预测（规则引擎回答不了）、第二标注人（n=16 且标注与规则同作者，存在同源风险，
REPORT.md 开头已声明）。指标只说明「规则与人工直觉的方向一致性」，不说明「能预测流量」。

## 4. 关键取舍

1. **词典而不是模型打分**：可复现、可解释、零成本、可评测；LLM 打分是黑盒且不能给自己生成的内容打分；
2. **演示模式兜底**：BYOK 有跨域和付费门槛，演示数据保证「打开就能看懂价值」；
3. **12 条而不是 50 条**：选题是筛出来的不是堆出来的，搭配排序和状态管理更接近真实工作流；
4. **每条选题带风险提醒**：AI 容易只讲好处，产品层面强制它讲「这条选题哪里可能翻车」。

## 5. 边界

- 打分器是词典规则：覆盖不到的新句式会误判（评测抓到过一次，已修；报告里写着效度声明）；
- AI 生成基于你的文字描述，**不抓取真实热点数据**——它不知道今天热搜是什么；
- 数据全部存在本机浏览器 localStorage，清浏览器数据 = 清空选题池；
- 发布前请人工判断：分数回答「标题像不像会被点开」，不回答「内容能不能立得住」。

## 6. 如果继续做

- 接热榜类公开数据源（M2 评估合规与维护成本）；
- 5 人使用访谈：验证「10 分钟完成周选题」的北极星与诊断文案可读性；
- 第二标注人交叉标注，把同源风险的口径补齐。
