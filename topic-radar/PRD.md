# 选题雷达 TopicRadar · PRD

> 版本 v1.0 ｜ 2026-11-02 ｜ 作者：Aurorawby（AI 结对编程）
> 一句话：**给单兵博主的 AI 选题工坊——AI 按账号定位生成候选，规则引擎给标题打可解释的分。**

---

## 1. 背景与问题

单兵创作者（公众号 / 小红书 / 知乎）每周最痛的不是写，而是「不知道写什么」：

- 选题靠拍脑袋或刷同行，一晚上刷了 40 条视频，产出 0 条可用选题；
- 市面上的「爆款标题生成器」直接吐标题，**不解释为什么**——用了也不知道下一条怎么自己想；
- 通用大模型能生成选题，但一次给 20 条平均水平的，没有筛选标准，反而增加决策负担。

**机会**：把「生成」和「判断」拆开——AI 负责按定位生成候选（发散），规则引擎负责按爆款标题的
常见特征打分排序（收敛），人只做最后的判断。

## 2. 目标用户与场景

| 谁 | 场景 | 频率 |
|---|---|---|
| 单兵博主（副业 / 学生） | 周日晚定下周选题：填一次账号定位 → 生成 → 挑 3 条 → 标好状态 | 每周 1-2 次 |
| 内容运营（1-3 年） | 写稿卡壳：把写好的标题丢进打分器，看缺哪个特征再改 | 随手用 |
| 我自己（求职者） | 把「选题-打分-看板」的产品方法论做成可演示的作品 | — |

## 3. 产品目标与指标

**北极星**：一次「打开 → 导出本周选题」的完成时长 ≤ 10 分钟。
**护栏**：打分器与人工判断的方向一致率 ≥ 80%（评测集）；AI 生成必须可关闭（无 Key 全流程可用）。
**信任指标**：用户能复述出「某维为什么低分」（诊断文案可读性，靠用户访谈验证，M2）。

## 4. 需求清单（P0 = 没有它产品不成立；P1 = 显著增值；P2 = 以后再说）

| 级别 | 需求 | 验收标准（可测试） |
|---|---|---|
| P0 | 标题打分器：6 维规则评分 + 加权总分 + 诊断建议 | 任意标题输入 → 输出 6 个 0-5 维度分 + 0-100 总分 + ≤2 条建议；评测集（16 条标注）双命中率 100%、区分度 ≥ 25 分 |
| P0 | 演示模式：无 API Key 可走完全流程 | 全新浏览器、不填 Key：装载 8 条演示选题 → 打分 → 看板 → 导出，全程无报错；演示标题评分与评测集一致（≥ 阈值） |
| P0 | 选题池管理：状态流转 + localStorage 持久化 | 待写 → 在写 → 已发 → 弃可循环流转；刷新页面状态不丢；删除有确认 |
| P0 | 导出：一键复制 Markdown / 下载 .md | 导出含账号设定 + 全部选题（状态/标题/类型/评分/逻辑），可直接贴进备忘录 |
| P1 | AI 生成：按账号定位生成 12 个候选（BYOK） | 支持 OpenAI 兼容接口（智谱/DeepSeek/Moonshot/Ollama/自定义）；返回非 JSON 时展示错误而非崩溃；Key 只存本机 |
| P1 | 生成结果自动打分排序 | AI 返回的每条自动过规则引擎，卡片按总分降序；评分不由模型给出 |
| P1 | 追问：单条选题要 3 个标题变体 / 200 字大纲 | 变体逐条带规则评分；失败展示错误信息并保留原选题 |
| P1 | 看板：类型分布 + 状态漏斗 + 已发率 | 有选题时渲染；空池显示引导文案 |
| P2 | 接热点数据源（热榜 / 关键词指数） | M2 评估：需要后端或可信公开接口，先不做 |
| P2 | 多账号 / 多选题池切换 | 等单池用出真实痛点再做 |
| P2 | 打分维度自定义权重 | 等有用户反馈「权重不合理」再做 |

## 5. 明确不做（Not-doing）

- **不做流量预测**：词典规则只能回答「像不像会被点开的标题」，回答不了「发了能多少阅读」——页脚明示；
- **不做账号托管 / 自动发布**：不做平台 API 接入（合规与授权成本远超单兵场景价值）；
- **不做标题党优化器**：情绪维建议里明确「别做夸张标题党」，不做「夸张度加成」；
- **不建账号体系、不上传任何数据**：全部状态存 localStorage，清浏览器数据即清空（说明里写明）。

## 6. 关键设计决策

1. **生成（AI）与判断（代码）分离**：AI 只产出标题/逻辑/风险等文本，分数全部由规则引擎现算——
   模型不能给自己的产出打分，保证「解释」这一层的可信度；
2. **规则默认、模型可选**：打分器 + 演示数据离线可用，零成本先拿到 80% 价值（与面试复盘器同一架构）；
3. **评分可解释**：每维给出「命中了什么 + 怎么补」的具体建议，而不是一个黑盒百分比；
4. **同源风险写进报告**：评测的标注与规则出自同一作者，REPORT.md 开头就声明——
   指标只说明「方向一致性」，不说明「预测流量」（诚实红线，与作品集其他产品同口径）。

## 8. 风险与对策

| 风险 | 对策 |
|---|---|
| 词典覆盖不到新句式 → 误判 | 页面 + 报告明示规则边界；评测集随迭代扩充；弱维度给「不加也行」的免责话术（如时效维） |
| 用户提供 Key 后被计费 | 默认推荐免费档（智谱 glm-4-flash）；max_tokens 限制在 3000/800；提示 Key 只存本机 |
| AI 返回非 JSON / 超时 | 提取器容忍 ```json 包裹与前后缀文本；错误原样展示 + 提示换供应商或用演示模式 |
| 用户把高分当保证 | 产品说明与页脚声明：分数只回答「标题特征」，内容质量与时机不在评分范围 |

## 9. 里程碑

- **M1（已完成，本版本）**：P0 全部 + P1 全部 + 评测（16 条，双 100%，区分度 40.5）；
- **M2（有真实用户反馈后）**：热点源接入评估、5 人使用访谈（北极星时长 + 诊断可读性）、维度权重可配置。

## 10. 本 PRD 的局限

- 用户画像来自我自己和同类工具的评论调研，没做过正式访谈（M2 补）；
- 北极星指标（10 分钟完成）当前没有埋点验证——纯前端可加本地埋点，列入 M2；
- 评测集 16 条由作者本人标注，换人标注可能不一致，暂无第二标注人。

## 竞品分析（2026-11 补充）

> 口径：基于公开产品能力的定性对比，未做付费/深度评测。

| 替代方案 | 它强在哪 | 在我们场景里的不足 | 我们的差异 |
|---|---|---|---|
| 新榜 / 灰豚 / 巨量算数 | 平台数据、热度、榜单成熟 | 给的是数据，不是“这个选题为什么能爆/有什么风险” | 生成候选选题 + 6 维规则打分 + 风险提醒 |
| 小红书灵感 / 创作中心 | 站内热点和选题参考 | 不可跨平台，判断逻辑不透明 | 规则维度可解释，能解释“缺什么” |
| ChatGPT | 能一次给很多选题 | 不稳定、不懂平台语境，难判断好坏 | 规则打分器负责判断，AI 只负责生成候选 |

**结论：** 不是“热点榜单”，是“把热点翻译成可执行选题”的判断工具。
