# Quiz Factory 数据版 产品说明（作品集版）

> v1 的单文件测试有个"幸福的烦恼"：因为零服务器、零数据采集，它**拿不到任何真实数据**——
> PRD 里的完成率、分享率、题目区分度全都停留在假设上。数据版是回答这个问题的 v2：
> 同一套测试、同一套计分算法，加上真后端（API + 数据库），换来看板上的真实数据。

## 1. 一句话

**给测试工厂装上后端和数据看板**：答题匿名入库，创作者实时看到完成漏斗、逐题选项分布、结果分布——把"我觉得哪道题好"变成"数据显示哪道题在打酱油"。

## 2. 这在作品集里补上了什么

| 维度 | v1（单文件版） | v2（数据版） |
|---|---|---|
| 架构 | 纯前端单文件 | FastAPI + SQLite + 前端三页，前后端分离 |
| 数据 | 0 采集（隐私卖点） | 匿名采集（隐私分层设计） |
| 指标 | 只能假设 | 完成率 / 题目区分度 / 结果分布，真实可测 |
| 接口 | 无 | 5 个 REST 接口 + 自动生成的接口文档（/docs） |

**关键产品决策——隐私分层**：单文件版继续 0 记录（介意数据的人玩它）；数据版页面在开始前**明示**"会匿名记录作答"，且只存三类信息：开始了、答完了、每题选了哪个。不存 IP、不存账号、不用 Cookie。让"愿意用数据换改进的人"有得选，这是对 v1 隐私原则的继承而不是背叛。

## 3. 架构与接口

- **后端**：FastAPI（自动生成 Swagger 文档 `/docs`）+ SQLite（单文件数据库，`db.sqlite3`，删掉即清零）；
- **数据管道**：`prepare.py` 从 v1 测试库加工种子数据，校准/稀有度算法与 v1 完全一致（保证两个版本结果可对照）；
- **接口**（5 个）：
  - `GET /api/quizzes` 列表（含开始/完成人数）
  - `GET /api/quizzes/{slug}` 测试完整数据
  - `POST /api/quizzes/{slug}/start` 建匿名会话 → session_id
  - `POST /api/quizzes/{slug}/finish` 提交逐题选项/结果/用时
  - `GET /api/quizzes/{slug}/stats` 看板聚合（漏斗/分布/逐题）
- **前端**：测试库 / 答题页 / 数据看板三页，与后端同源直出；看板每 8 秒自动刷新。

## 4. 数据怎么用（PM 视角）

| 看板指标 | 能做的产品决策 |
|---|---|
| 完成率（开始 → 完成） | 掉人严重的测试：题数是否超 10、第几题流失最狠 |
| 逐题选项分布 | 某个选项几乎没人选 → 题目区分度不足，重写该题 |
| 结果分布 | 某种结果占比异常 → 调整选项分值或阈值 |
| 平均用时 | 判断"2 分钟"的宣传是否属实 |

## 5. 边界与下一步

- 本地单机版面向作品集演示与同学试玩；公网部署（Render/Railway 免费档）是发布动作，不是开发动作；
- 并发写入用的是 SQLite 单文件，演示量级（百人内）完全够；真上量再换 PostgreSQL；
- M2：把生成器 create.html 接上 `POST /api/quizzes`，做到"浏览器里生成 → 一键发布到数据版站点"的完整闭环。
