# 吃什么决策器 FoodPicker · PRD

> 版本 v1.0 ｜ 2026-11-06 ｜ 作者：Aurorawby（AI 结对编程）
> 一句话：**「今天吃什么」是全球最高频的决策难题——解法不是推荐算法，是把产品经理的多准则决策矩阵做成每天都能用的工具：候选打分 → 硬约束过滤 → 调权重 → 加权排序出结果，纠结到底就交给天意。**

---

## 1. 背景与问题

「今天吃什么」的痛苦不是没有选项，是**选项没有结构**：

- 脑子里有 5-6 家候选，但每家的优点缺点不在同一个维度上比（这家好吃但远、那家近但排队）；
- 硬约束总在最后才想起（「哦这家有香菜」「这家超预算了」）；
- 纠结到最后往往随机选一个，还觉得不该选它——**决策疲劳的解药不是更多信息，是结构化的少信息 + 一个终止机制**。

**机会**：多准则决策矩阵（加权评分法）是产品经理的基本功。把它做成 30 秒能用的工具，
顺便让「权重」「硬约束 vs 软偏好」「tie-break」这些决策概念变得可触摸。

## 2. 目标用户与场景

| 谁 | 场景 | 频率 |
|---|---|---|
| 所有人 | 今晚吃什么 / 周末去哪吃 | 每天 |
| 群体决策 | 几个人口味不一：约束（忌口/预算）先行过滤，再看排序 | 每周聚餐 |

## 3. 产品目标与指标

**北极星**：从打开到「今晚吃这家」≤ 60 秒（候选已存时 20 秒）。
**正确性护栏（可测试）**：硬约束过滤、加权排序、tie-break 与手工计算完全一致（确定性回归）。
**信任指标**：决策结果的「为什么」可读——每个 winner 都能说出最强维度和相对短板。

## 4. 需求清单

| 级别 | 需求 | 验收标准（可测试） |
|---|---|---|
| P0 | 候选管理：名称 / 人均 / 四维主观分（想吃·顺路·预算合·不排队，1-5）/ 忌口标签，本地保存 | 增删改即时持久化 |
| P0 | 硬约束过滤：预算上限、忌口标签（子串匹配）、顺路下限；被拒候选展示被拒原因 | 过滤结果与原因与手工判定一致（回归评测） |
| P0 | 加权排序：四维权重滑条（0-5）归一化加权，并列时「不排队」优先（固定 tie-break 保证可复现） | 排序与总分与手工计算一致 |
| P0 | 结果卡：winner + 各维度条形拆解 + 「为什么是它」（最强维度/相对短板） | 文案与数据一致 |
| P0 | 被拒清单：展示谁因什么被筛掉 | 全被筛掉时有明确指引（放宽约束） |
| P1 | 天意模式：约束内等权随机一个，配「不许再刷」的仪式文案 | 随机不评测（非确定），文案固定 |
| P1 | AI 点菜：按人数 / 预算 / 忌口生成点菜清单 | JSON 容错；建议仅供参考文案 |
| P1 | 演示候选：6 家（含超预算 / 含忌口样本，演示过滤） | 装载即过滤可见 |
| P2 | 历史记录（今天吃了什么，喂回想吃度） | M2：与「数据回流」理念同源 |
| P2 | 群体模式：多人各自打分取均值 | 等真实场景反馈 |

## 5. 明确不做（Not-doing）

- **不做餐厅推荐数据库**：不接入 POI 数据源——候选来自用户自己的真实清单（「垃圾进垃圾出」页面明示）；
- **不做个性化推荐算法**：权重是用户自己拉的——工具透明化决策，不黑盒替用户决策；
- **天意模式不评测**：随机过程非确定，不进回归；
- **不做社交 / 排行**：工具不是社区。

## 6. 关键设计决策

1. **多准则决策矩阵而不是评分推荐**：用户看到的是「你的分数 × 你的权重 = 你的排序」——
   透明、可解释、改权重结论会变；这是 PM 决策方法论的活教材；
2. **硬约束先于软偏好**：忌口和预算是过滤条件（一票否决），不参与打分——把「绝对不能接受」和「稍微差点」分开，
   是决策质量的一半；
3. **tie-break 固定为「不排队优先」**：并列必须有确定性的次序，否则结果不可复现、评测无从断言；
4. **天意模式是功能不是玩笑**：决策疲劳的学术解法之一是「随机化 + 承诺」——选中的不再纠结，
   这是对「加权排序」的补充（信息不足以区分时，随机 + 承诺就是最优解）。

## 7. 页面流程（低保真线框）

```
┌──────────────────────────────────────────────┐
│ ① 候选表：名称|人均|想吃|顺路|预算合|不排队|标签  │
│    [➕加一家]（本地自动保存）                    │
├──────────────────────────────────────────────┤
│ ② 约束：[预算上限][忌口][几人][顺路下限]        │
│    权重滑条：想吃3 顺路2 预算2 不排队1          │
│    [🍽决策！] [🎲交给天意]                     │
├──────────────────────────────────────────────┤
│ ③ 结果卡：今晚就吃 巷子口重庆小面               │
│    为什么：想吃最高(4/5)，短板不排队(2/5)       │
│    已过滤 3 家：日料(超预算)、老王(忌口香菜)…    │
│    维度条形 ×4 ｜ 备选 2 家                    │
│  [📝AI 点菜]                                  │
└──────────────────────────────────────────────┘
```

## 8. 风险与对策

| 风险 | 对策 |
|---|---|
| 用户评分本身不准（垃圾进垃圾出） | 页面明示「评分是你的主观输入」；工具的价值是结构化对比，不是替你了解口味 |
| 权重全 0 | 归一化兜底为等权（不崩溃） |
| 并列导致结果「看起来随机」 | 固定 tie-break（不排队优先）+ 文档说明，保证可复现 |
| 忌口子串匹配误伤（「辣」匹配「微辣」也可能匹配「不辣」） | 提示用户标签粒度自己定（「辣」vs「不辣」是标签的语义，工具只做匹配）；M2 支持排除语义标签 |
| AI 点菜不靠谱 | 建议仅供参考文案常驻 |

## 9. 里程碑

- **M1（已完成，本版本）**：P0 全部 + P1 全部 + 确定性回归评测；
- **M2**：历史记录回流（吃过 → 更新想吃度）、群体打分均值、排除语义标签。

## 10. 本 PRD 的局限

- 四维评分是主观输入，工具不验证真伪；
- 样本量小（6 家候选）时排序差异可能不显著——工具给的是「结构化的比较」，不是统计结论；
- 忌口匹配是子串级，「不辣」含「辣」的语义问题由用户标签粒度自行控制；
- 随机模式不进评测（非确定过程），其价值是决策终止机制而非算法。

## 竞品分析（2026-11-06 补充）

> 口径：基于公开产品能力的定性对比，未做付费/深度评测。

| 替代方案 | 它强在哪 | 在我们场景里的不足 | 我们的差异 |
|---|---|---|---|
| 美团 / 大众点评 | 商家数据、评价、配送 | 推荐是平台目标，不是你的多准则决策；忌口/预算不透明 | 候选自定、权重可调、硬约束可解释 |
| 随机转盘 / 骰子 | 解决选择困难、有趣 | 不处理忌口/预算，也不解释结果 | 先过滤再加权排序，tie-break 可复现 |
| Excel 打分表 | 自由、可算 | 要自己搭公式，权重/边界易错 | 开箱即用的决策矩阵 + 可解释 why |

**结论：** 不是推荐算法，是「把纠结变成可解释决策」的多准则工具。
