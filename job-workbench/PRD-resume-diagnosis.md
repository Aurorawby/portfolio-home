## 1. 背景与问题

找实习的人常见困境不是“没有经历”，而是：

1. 不知道目标 JD 到底要什么；
2. 简历写了，但和 JD 对不上；
3. 有校园经历/比赛，不知道怎么讲成岗位能看懂的证据；
4. 直接让 AI 改简历，容易被编经历、编数字。

前期访谈（样本很小，只作方向）：

- 5 位想找实习的同学，当面 + 问卷；
- 反馈集中在“简历要按 JD 包装，否则 HR 不翻”；
- 3 位 0 实习同学用旧版工作台后，自己改简历、投产品/内容/选品运营，1–2 周内拿到实习 offer；
- 用户原话：“校园经历终于能写成岗位要的能力了。”

边界： 3 人、无对照，不能证明“工具导致 offer”；只能说明需求真实存在。

---

## 2. 目标用户

不限制实习段数和方向。 只要需要把经历讲成岗位能看懂的证据，都可以用。

优先服务：
- 0–1 段实习，正在找产品/运营/内容/数据等实习的本科生/研究生；
- 有校园经历、比赛、项目，但不知道怎么对应岗位；
- 已有实习，但简历和 JD 对不上，需要重新组织证据的人。

不适合：
- 需要自动投递/自动面试的人；
- 只想让 AI 编一段经历的人。

---

## 3. 产品目标

让用户在 20–30 分钟内完成：

1. 看清目标 JD 要什么；
2. 找出自己简历里“没有证据”的地方；
3. 用 1–2 个问题补一段真实证据；
4. 得到「原文 | 修改后 | 为什么」的建议，而不是直接替换；
5. 用招聘方视角做一次 30 秒检查。

非目标：
- 不自动投递；
- 不自动生成“能直接交”的简历；
- 不替用户编经历、数字、技能；
- 不做“万能求职平台”。

---

## 4. 核心流程

```
输入 JD + 原始简历
  → 生成分析 Prompt（或配置 API 直接分析）
  → 粘贴四列表格
  → 解析缺口
  → 选一个缺口，按 S/T/A/R 一次问 1 个问题
  → 生成改写 Prompt / 直接改写
  → 粘贴「原文 | 修改后 | 为什么」
  → 招聘方 30 秒检查
  → 导出诊断记录
```

---

## 5. 功能需求

### P0：JD × 简历分析

- 输入 JD、原始简历；
- 生成一段固定 Prompt，要求四列表格：
  `JD 要求 | 我的对应经历 | 证据是否充分 | 需要补充什么`；
- 缺证据必须写“待补充”，禁止编造；
- 支持把 AI 返回的 Markdown 表格粘回来并解析。

验收：
- 能识别表头与至少 3 行数据；
- 无表格时给出明确错误；
- 不把“未提供”写成“有”。

### P0：缺口 → 1 个问题

- 从解析出的缺口里选一个；
- 一次只显示 S/T/A/R 中的一个问题；
- 不记得数字可写“不记得/待补充”；
- 回答存本机，可继续下一个问题。

验收：
- 刷新页面回答不丢；
- 不出现一次问 4 个问题；
- 不把“不记得”自动改写成数字。

### P0：改写建议

- 生成改写 Prompt，要求输出：
  `原文 | 修改后 | 为什么这样改`；
- 明确要求“不新增事实、不编数字、只改结构和表达”；
- 用户自己粘贴结果，不自动覆盖原简历。

验收：
- 输出中能看到原文与修改后的对应；
- 没有原文依据的句子会被标“待补充”。

### P1：最终简历生成

- 用户确认改写建议后，可以生成一版最终简历；
- 只使用已核对/已确认的内容；
- 提供复制/下载，不自动替换原文件；
- 生成前提示“再检查一遍数字和事实”。

验收：
- 最终版能追溯到原文与用户回答；
- 没有依据的句子不会自动补；
- 不自动投递。

### P0：招聘方检查

- 8 项检查清单：
  目标岗位、动作+结果、空话、数字出处、JD 对应、虚构、长度、追问可解释；
- 勾选状态保存；
- 可复制完整诊断记录。

### P1：模型设置（可选）

- 支持智谱/DeepSeek/Moonshot/Ollama/自定义 OpenAI 兼容接口；
- Key 只存 localStorage；
- 不配 Key 也能用复制 Prompt 的离线方式。

### P1：示例数据

- 一键填入示例 JD + 示例简历，方便测试者不用从空白开始；
- 示例不包含真实姓名/公司/联系方式。

### P2：经历库联动

- 把 Step 2 补出来的回答写回经历库/故事库；
- 避免重复填同一段经历。

### P2：版本对比

- 保存“改写前/改写后”，下一次打开可对比；
- 只在本机保存。

---

## 6. 指标

当前阶段（原型）：
- 5 人任务测试完成率；
- 首次生成分析结果的耗时；
- 每个缺口回答完成率；
- 用户是否把改写建议真正用进简历（自报）；
- 最卡的一步。

后续（有真实用户后）：
- 7 天内改简历比例；
- 投递后拿到面试的比例（需对照，不能归因）；
- 复用率：第二次打开；
- 导出/复制率。

不宣称：
- “提升通过率 X%”；
- “用户留存 X%”；
- “AI 让简历更牛”。

---

## 7. 风险与边界

| 风险 | 处理 |
|---|---|
| AI 编经历/数字 | Prompt 强制“待补充”；改写只给建议；用户确认 |
| 用户把 AI 建议直接投 | 页面明确“先核对，再使用”；不自动投递 |
| Key 泄露 | 只存本机；提示不要在公共电脑使用 |
| 访谈样本小 | 只写“5 人访谈 + 3 人使用反馈”，不写“验证” |
| 用户嫌步骤多 | 目标是 20–30 分钟；后续可做“快速模式” |

---

## 8. 不做什么

- 不自动投递；
- 不未经确认自动替换原简历；
- 不编造经历/数字；
- 不做“万能求职平台”；
- 不把“模拟招聘方”说成真 HR。

## 10. 面试讲法（30 秒）

> “我做了一个简历诊断工具，不是直接替人改简历：先把 JD 和原始简历对照，找出没有证据的格子；再按 S/T/A/R 一次问 1–2 个问题；最后只给「原文 | 修改后 | 为什么」。  
> 5 位同学访谈 + 3 位 0 实习同学使用反馈，说明‘校园经历不知道怎么写成岗位证据’是真实需求；但样本小，我不把它说成验证有效。”
