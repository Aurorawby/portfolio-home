# 求职访谈 Agent PRD（MVP）

| 项 | 内容 |
|---|---|
| 产品 | 求职工作台 · 访谈 Agent |
| 版本 | v0.1 设计稿 |
| 目标 | 把“固定 5 问”改成“会根据回答决定下一问”的访谈 |
| 入口 | 求职工作台 → 简历诊断 / 经历深挖 |
| 状态 | 设计完成，待实现自适应追问 |

---

## 1. 为什么不是普通工作流

现在求职台是：

> 填 JD → 点按钮 → 固定 5 问 → 生成故事

它没有“判断下一步”的能力。真正的访谈 Agent 至少要具备：

1. **记忆**：记得 JD、简历、已答内容、还缺什么；
2. **选择**：根据缺口决定下一问问什么；
3. **追问**：回答太泛/没数字/没个人贡献时，再追一层；
4. **工具**：读 JD、匹配经历、写故事库；
5. **停止条件**：问够了就停，不无限追问；
6. **人确认**：用户可以跳过、改答案、停止。

---

## 2. 目标用户

不限制实习段数和方向。只要需要把经历讲成岗位能看懂的证据，都可以用。

优先服务：
- 正在找产品/运营/内容/数据等实习的本科生/研究生；
- 有校园经历、比赛、项目，但不知道怎么讲成岗位证据；
- 已有实习，但简历和 JD 对不上，需要重新组织证据；
- 不想被 AI 编经历，只想把真实经历讲清楚。

---

## 3. Agent 循环

```
读 JD + 简历 + 故事库
  → 识别证据缺口（能力/数字/个人贡献/冲突）
  → 选优先级最高的一个缺口
  → 问 1 个 S/T/A/R 问题
  → 判断回答：
       太泛 → 追问一层
       没数字 → 问范围/不记得
       没个人贡献 → 问“哪部分是你独立做的”
       够了 → 存成故事卡
  → 还有缺口且未到停止条件 → 下一问
  → 够用/到上限 → 输出故事卡 + 剩余缺口 + 下一步
```

---

## 4. 状态字段

```text
jd              目标岗位
resume          原始简历
stories[]       已保存的故事
gaps[]          证据缺口
asked[]         已问过的问题
answers{}       回答
current_gap     当前缺口
question_count  已问轮数
stop_reason     够写最终简历 / 到上限 / 用户停止
```

---

## 5. 提问策略（规则版，不依赖模型）

### 5.1 先选缺口
优先级：
1. JD 要求但简历完全没证据；
2. 有经历但没数字/结果；
3. 有结果但个人贡献不清；
4. 有动作但没冲突/取舍。

### 5.2 再选问题
- S：当时遇到什么问题？背景是什么？
- T：你具体负责什么？目标是什么？
- A：你做了什么？协调了谁？
- R：结果是什么？有数量/金额/时间/效率吗？

### 5.3 追问规则
- 回答 < 30 字：追问“能具体一点吗？先做什么、后做什么？”
- 回答没有数字：追问“有没有大概范围？不记得也可以写不记得。”
- 回答全是“我们”：追问“哪部分是你独立做的？”
- 回答没有冲突：追问“当时最卡的是什么？怎么处理的？”

### 5.4 停止条件

- Agent 判断：现有证据已经足够写一版最终简历；
- 或已形成 2 个可用故事；
- 或已问 8 个问题；
- 或用户点“够了，先到这里”。

**默认优先级：**
1. 用户手动停；
2. Agent 判断“够写最终简历”；
3. 到达问题上限。

“够写最终简历”不是“问满 8 个”，而是：
- 至少 1 段核心经历有背景、动作、结果；
- 关键数字有出处，或者明确写“不记得”；
- 个人贡献能说清；
- 目标 JD 的核心要求至少对上 2 条。

---

## 6. 输出

- 每个故事：30 秒版 + 90 秒版 + 可能追问 + 待补项；
- 剩余缺口清单；
- 一版可编辑的最终简历（仅使用已确认内容）；
- 下一步建议：先补哪个缺口、去投哪类岗位；
- 可选：保存到经历库。

**最终简历规则：**
- 只使用用户确认过的内容；
- 没数字就写“不记得/待补充”，不硬编；
- 生成后由用户自己检查，不自动投递。

---

## 7. 指标

| 指标 | 定义 |
|---|---|
| 完成率 | 用户完成至少 1 个故事 |
| 到可用故事的轮数 | 平均问几轮能得到一个能讲的故事 |
| 追问相关性 | 用户评分 1–5：追问是否基于上一句 |
| 意外细节率 | 用户说“这个我自己都没想到”的比例 |
| 中途退出率 | 问到第几轮退出 |
| 愿不愿意再用 | 会/看情况/不会 |

**不宣称：** 面试通过率、offer 转化；样本小，不能归因。

---

## 8. 不做什么

- 不自动投递；
- 不替用户编数字/经历；
- 不无限追问；
- 不做“AI 面试官”假装真人；
- 不把固定 5 问包装成 Agent；
- 最终简历必须由用户确认后再生成，不自动替换原文件。

---

## 9. 5 人测试任务

每位找实习同学，30 分钟：

1. 输入一个目标 JD + 一段真实/示例经历；
2. 让 Agent 问到形成 1 个故事；
3. 看故事卡和剩余缺口；
4. 评分：追问相关性、是否问出没想到的细节、是否愿意再用。
