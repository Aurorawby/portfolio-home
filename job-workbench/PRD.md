# 求职工作台 · PRD

## 1. 背景

三个求职工具已经各自能用：JD 雷达（看市场要什么）、模拟面试官（生成题）、面试复盘器（面完复盘）。
但真实求职是**连续流程**，分开用有三个摩擦：

1. **重复输入**：同一份 JD 要在三个页面各粘一次，简历要粘两次；
2. **结论散落**：雷达的 gap、生成的题、复盘出的薄弱项分别在三个页面，面试前要翻三处；
3. **不知道下一步**：做完一步后，不清楚该去哪个工具、还差什么。

这三个摩擦不解决，三个工具就只是"三个 demo"，不是"一条求职流程"。

## 2. 目标用户

正在求职的 AI 产品岗候选人（我自己 + 同学）。

## 3. 目标与非目标

**目标**

1. 一页看清三步进度（JD 扫描 / 生成题 / 复盘）；
2. **输入一次，三个工具共用**；
3. 自动汇总成一份「求职档案」（Markdown），面试前 10 分钟能过一遍；
4. 预测面试题能一键带入复盘器。

**非目标**

- 不重写三个工具的逻辑（避免三个页面代码合并成一个巨型页面）；
- 不做账号/云端同步（求职数据留在本机更安全）；
- 不做面试日历/提醒（下一步再说）。

## 4. 方案：编排层，不是第四个工具

| 层 | 归属 | 职责 |
|---|---|---|
| 能力词典 / 雷达 | JD 雷达页面 | 分析 JD，写 `jd_last` 摘要 |
| 题库 / 生成 | 模拟面试官页面 | 生成题，写 `mock_interview_state_v1` |
| 复盘编辑 | 面试复盘器页面 | 记录真实问题，写 `ir_state` |
| **编排 + 汇总** | **工作台** | 读写共享 localStorage，展示进度，生成档案 |

**共享键**：`jwb_state`（JD/简历）、`jd_last`、`mock_interview_state_v1`、`ir_state`。
工作台只做三件事：读、汇总、写回（带入）。

这样每个工具仍然可以单独使用，工作台只是一个"主线入口 + 汇总器"，**不重复实现逻辑**。

## 5. 关键交互

1. 工作台填 JD + 简历 → 点「保存并带给工具」→ 一键写入三个工具需要的键；
2. 点「去扫描 JD」→ JD 雷达自动带出 JD → 分析后写 `jd_last`；
3. 点「去生成面试题」→ 模拟面试官自动带出 JD + 简历；
4. 点「把预测题带入复盘」→ 合并进复盘器（按题目去重），类型先标「待分类」；
5. 回到工作台刷新 → 三步状态 + 汇总数字更新；
6. 导出 / 复制「求职档案」。

## 6. 指标设计

| 层级 | 指标 | 怎么衡量 |
|---|---|---|
| 流程 | 三步完成率 | 三步都完成的用户 / 打开工作台的用户（需埋点，暂本地统计） |
| 效率 | 重复输入次数 | 目标降为 **0**（一次输入，三处复用） |
| 产出 | 档案导出/复制率 | 导出按钮点击 / 完成三步的用户 |
| 质量 | 集成测试 | `node eval/job-workbench/run.mjs` 验证数据流 |

## 7. 风险与边界

- 数据只在**同一浏览器同源**下共享；换浏览器/清缓存会丢；
- 「清空本地数据」会同时清掉三个工具的数据，需要二次确认；
- 带入复盘器的题型是「待分类」，需要用户自己改；
- 工作台本身不产生内容，价值来自三个工具——所以三个工具的质量决定上限。
