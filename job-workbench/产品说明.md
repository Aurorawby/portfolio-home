# 求职工作台 · 产品说明（作品集版）

> 一句话：**把「JD 雷达 → 经历深挖 → 模拟面试官 → 面试复盘器」串成一条线**，
> 输入一次 JD + 简历，自动汇总出一份能带走的「求职档案」。

---

## 1. 为什么做

三个工具各自都能用，但真实求职是连续流程，分开用有三个摩擦：

- 同一份 JD 要粘三次，简历要粘两次；
- 雷达的 gap、生成的题、复盘出的薄弱项散在三个页面，面试前要翻三处；
- 做完一步不知道下一步去哪。

**"三个能用的工具"和"一条能走通的流程"是两回事**——这个页面做的就是后者。

## 2. 我做成了什么

| 能力 | 实现 |
|---|---|
| 三步进度 | 每一步完成状态自动点亮（JD 扫描 / 生成题 / 复盘） |
| 输入一次 | JD + 简历写一次，三个工具自动带出 |
| 数据共享 | 四个 localStorage 键共用；各工具仍可单独使用 |
| 预测题带入复盘 | 一键把生成的题合并进复盘器（按题去重） |
| 求职档案 | 自动汇总 JD 高频能力、预测题、真实复盘、薄弱清单、下一步行动；可复制/导出 Markdown |
| 经历深挖 | 5 个问题把实习聊成 STAR 故事 + 30/90 秒版本 + 追问 + 待补证据；离线可用，AI 润色可选 |
| 经历库 | 保存多段故事，按能力标签 / 目标 JD 汇总；导出面试故事库 Markdown；规则匹配，只做提示 |

**关键取舍：编排而不是合并。** 没有把三个页面的代码复制成一个巨型页面，而是让每个工具保持单一职责，
工作台只做「读、汇总、写回」。这样单改一个工具不会拖垮其他两个，也避免了 2000 行的大杂烩。

## 3. 验证

| 检查 | 结果 |
|---|---|
| 数据流集成测试 | ✅ 读取三工具数据 / 档案章节完整 / 导出正确的薄弱题 / 预测题带入复盘去重正确 |
| 经历深挖逻辑测试 | ✅ 5 问流程 / 弱动词识别 / 不编数字 / STAR 与 Markdown 生成 |
| 经历库测试 | ✅ 能力标签 / JD 覆盖 / 故事库 Markdown 导出 |
| 复现 | `node eval/job-workbench/run.mjs` |

**没有做的**：真实用户完成率（需要埋点 + 真实用户），简历里不写"三步完成率 80%"这种未测数字。

## 4. 边界

- 数据只在同一浏览器同源共享，换设备会丢（求职数据本就该留在本机）；
- 「清空数据」会同时清三个工具的数据，有二次确认；
- 带入复盘器的题型是「待分类」，需要自己改；
- 工作台不生产内容，价值上限由三个工具决定。

## 5. 如果继续做

- 本地埋点：三步完成率、档案导出率（纯前端，不上传）；
- 面试日历：把面试时间存本地，提前提醒复习；
- 档案导出一页 PDF（面试前打印）。
