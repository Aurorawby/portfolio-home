# 行程一页纸 · 产品说明（作品集版）

> 一句话：**粘贴收藏的旅行攻略 → 代码解析出景点/餐厅/住宿/交通与花费 → 诊断「排太满、漏吃饭、多日无住宿」→ 渲染成可打印带走的一页行程。自由文本交给 AI 抽取，结构判断由代码做。**

---

## 1. 为什么做

旅行前最乱的环节是攻略整理：收藏 8 篇小红书攻略，出发那天来回翻、漏吃饭、跑断腿。
这些是**结构问题**——「解析 → 诊断 → 渲染」这套方法论我在文献综述 Agent 和汇报一页纸上验证过两次，
旅行攻略是它的第三次迁移：**换场景不换方法，检验产品方法的可迁移性**。

## 2. 我做成了什么

| 模块 | 实现 |
|---|---|
| 攻略解析 | Day/第N天分隔、📍/序号条目、「门票/人均/营业」副信息自动挂靠、类型分类（景点/餐/住宿/交通/其他）、花费提取 |
| 结构诊断 | 单日景点 ≥4（偏满 ⚠️）、单日无餐（漏吃饭 ⛔）、多日无住宿、天数超出设定；每段合计花费 |
| 一页渲染 | 按天分组时间线、类型图标、每日/总花费、@media print 只打印行程 |
| AI 抽取（可选） | 乱格式自由文本 → 结构化 POI JSON（type 白名单校验、截断防脏数据）；抽取后仍过代码诊断 |
| 演示攻略 | 北京 2 日，Day 2 故意排 4 个景点——装载即触发「偏满」诊断 |

## 3. 验证（可复现）

`node eval/trip-onepager/run.mjs`（不调用模型、不依赖浏览器）：

| 检查 | 结果 |
|---|---|
| 攻略解析（天数 / 条目数 / 类型 / 花费合计） | 与手工标注一致 |
| 诊断触发（排太满 / 漏吃饭 / 超天数 / 全部通过） | 一致 |
| 副信息挂靠（门票/人均归入上一条目） | 一致 |

**诚实口径**：确定性回归测试；解析器认不全的行会进「其他」或不挂靠（不丢已识别内容）；
AI 抽取质量不做宣称（页面持续提示人工核对）。

## 4. 关键取舍

1. **规则解析优先、AI 兜底**：结构化攻略走确定性解析（快、免费、可测），只有乱文本才动用模型；
   且 AI 结果必须再过代码诊断——AI 产出不直接可信；
2. **诊断是核心功能而非附带**：「排太满/漏吃饭」是行程崩坏两大根因，把旅行老手的经验规则化；
3. **纸质一页**：旅途断网/分心场景下，纸是最可靠载体（与汇报一页纸同哲学）；
4. **不估算无价格条目**：合计只累加显式标价，不编造「大概」。

## 5. 边界

- 表格型 / 纯图片型攻略无法解析（图片需 OCR，超出单文件产品范围）；
- 类型词典覆盖常见词根，「什刹海」这类非常规命名的 POI 会进「其他」；
- 花费合计不含未标价条目；
- 诊断阈值（≥4 景点）是通用经验值，特殊人群节奏应自行调整。

## 6. 如果继续做

- 地理聚类：同区域条目自动归并到同一天（需地理编码，M2 评估）；
- 多攻略合并：两篇攻略的条目去重合并；
- 第二人标注解析口径（与文献 Agent 金标准同方法）。
