# 投递看板 · 产品说明（作品集版）

> 一句话：**实习 / 秋招投递的看板与复盘——漏斗转化率、渠道进面率、14 天无回音提醒、挂掉死因分布全部由代码现算，AI 只负责复盘建议和跟进话术。**

---

## 1. 为什么做

我的秋招 / 实习投递曾经是一团浆糊：投了谁、走到哪、为什么挂，全散在邮箱和聊天记录里。
Excel 能记账但不会算数——不告诉你投递→面试转化率、不告诉你哪家渠道在浪费时间、不提醒你哪家 20 天没下文该放下。

投递天然是个漏斗（投递 → 笔试 → 面试 → Offer）。**把漏斗做进工具，统计就是免费的；把「死因」做成必填字段，复盘才有抓手。**

## 2. 我做成了什么

| 模块 | 实现 |
|---|---|
| 看板 | 8 状态 Kanban（已投递→笔试→面试中→终面→HR 面→Offer / 挂了 / 无回音），卡片一键流转、自动更新停留日期 |
| 漏斗 | 各阶段到达数 + 简历过率 + 总 Offer 率，代码现算 |
| 渠道效果 | 各渠道「进面率」（到过面试及以后，或非简历关死亡），横向条形对比 |
| 跟进提醒 | 流程中停 >7 天、已投递 >14 天无下文，自动列进「该跟进」清单并标停在几天 |
| 死因分布 | 挂掉的记录按死因聚合降序——高频死因 = 下一轮要补的洞，页面直接提示配合「模拟面试官」练 |
| AI（可选） | 挂掉的 → 3 条可执行复盘建议；卡住的 → ≤80 字礼貌跟进话术；JSON 容错，失败不伤主功能 |
| 导出 | 一键复制 / 下载 Markdown 汇总（漏斗 + 渠道 + 全量记录 + 死因） |
| 演示数据 | 9 条覆盖全部状态，**日期相对今天生成**——任何时候装载都立即有效 |

## 3. 验证（可复现）

`node eval/application-board/run.mjs`（不调用模型、不依赖浏览器）：

| 检查 | 结果 |
|---|---|
| 漏斗统计（各阶段到达数、4 个转化率） | 与手工计算**逐字段一致** |
| 跟进提醒触发名单与排序 | 与人工标注（该提醒 3 条 / 不该 5 条）完全一致 |
| 渠道进面率（含「简历关死亡不计入」口径） | 一致 |
| 死因分布（含未记录兜底） | 一致 |

**诚实口径**：这是**确定性计算的回归测试**——保证统计代码与手工算的一致、防止以后改代码算错；
它不是「提效果」的评测（提醒阈值 14/7 天是经验设定，依据写在 PRD 风险表里）。

## 4. 关键取舍

1. **统计归代码，AI 归文案**：漏斗 / 提醒是数学，交给规则引擎才可测试；AI 只写它擅长的；
2. **手记而不是自动同步**：不做爬虫对接平台（合规 + 维护成本），记录成本压到 1 分钟；
3. **死因是下拉框不是自由文本**：8 个枚举让「死因分布」可聚合——自由文本复盘会变成日记；
4. **数据只在本机**：求职数据是敏感个人信息，清浏览器数据即清空，页面明示。

## 5. 边界

- 漏斗口径是「按当前状态计」：面试挂了不计入「到过终面」——口径简单但会低估，PRD 里写明了 M2 改进方向；
- 14 天 / 7 天阈值是经验值，不是平台承诺；
- 换设备 / 清浏览器数据会丢记录（单机设计）；
- AI 建议是通用方法论，不认识你的真实面试细节。

## 6. 如果继续做

- 与面试复盘器打通：面试卡片一键带去复盘；
- 「最高到达阶段」字段，修正漏斗低估；
- 死因填写率本地埋点（纯前端不上传）。
