# 模拟面试官 · PRD

## 1. 背景与问题

求职 AI 产品岗时，面试准备的真实痛点是：

- 不知道会被问什么：JD 写得很抽象，靠刷通用面经，问题对不上；
- 准备了答案但没准备好追问：面试官一追问就露馅；
- 复盘靠回忆：面完就忘，下次还犯同样的错。

现有工具：面经网站（别人的题，不针对你）、模拟面试 App（通用题库、要付费）、找学长模拟（时间难约、不可复用）。

## 2. 目标用户

- 主用户：正在准备 AI 产品面试的求职者/转岗者；
- 次用户：帮同学做模拟面试的人（拿生成清单当提纲）。

## 3. 目标与非目标

**目标**

1. 粘贴 JD + 简历，30 秒内生成一套**针对性**面试题（不是通用题）；
2. 每题带：考察点、答题框架、可能的追问；
3. 可自评、可记录、可导出，直接带去面试；
4. 默认纯前端离线，不上传简历和 JD（隐私是硬需求）。

**非目标**

- 不做实时语音对话（成本/体验不匹配 MVP）；
- 不评判回答好坏（需要模型 + 人工校准，先把"问什么"做好）；
- 不替代真实面试官。

## 4. 方案：规则层 + 可选 AI 层

**规则层（默认，离线）**

1. 用 **31 项能力题库**（每项含同义词 + 1 道能力题 + 1 个追问）匹配 JD；
2. 按"命中次数 + 命中的同义词数量"排序，取前 9 项生成岗位题；
3. **简历深挖题**：从简历里挑"像成果"的句子（含数字/提升/负责/主导）和与 JD 能力相关的句子，各出 1-2 道"你简历里写到「…」，具体讲讲"；
4. 固定补通用题：自我介绍、动机、短板、反问；
5. 汇总成 12-15 道题，带自评（1-5）和回答要点，导出 Markdown。

**AI 层（可选，自带 Key）**

把规则题 + JD + 简历发给模型，改写成更自然、更贴个人经历的问法，并补追问。
没有 Key 可以提供"AI 示例"（预置），**页面明确标注示例不是实时调用**。

**为什么规则层重要**：隐私、零成本、可复现；即使不填 Key 也能拿到 80% 的价值。

## 5. 指标设计

| 层级 | 指标 | 实测 |
|---|---|---|
| 生成质量 | 核心能力覆盖率 | **74.1%**（8 组 JD+简历，人工标注） |
| 生成质量 | 简历引用率 | **100%**（8/8 都生成了引用简历原句的深挖题） |
| 生成质量 | 追问完整度 | **100%** |
| 使用 | 平均题数 | 12.6 道/套（可"补 3 道"扩展） |
| 使用 | 导出率 | 导出 Markdown / 生成次数（后续埋点） |

**明确不宣称**：问题本身的"质量分"（需要人工评分，未做）。

## 6. 关键取舍

| 取舍 | 选择 | 理由 |
|---|---|---|
| 规则 vs 模型 | 规则默认，模型可选 | 隐私 + 零成本 + 可复现 |
| 题量 | 12-15 道 | 20 道以上准备不完；"补 3 道"做成可选项 |
| 追问 | 每题固定带 1 个 | 追问才是面试真正拉开差距的地方 |
| 简历个性化 | 引用原句，不改写 | 避免模型编造候选人没写过的经历 |

## 7. 风险与边界

- 题库 31 项，新能力词/新措辞会漏（已用"未覆盖能力"提示）；
- 引用简历原句可能断章取义，需要用户自己判断；
- AI 层会把简历发给服务商，页面明确提示"Key 只存本机、内容会发送给模型服务"；
- 生成的是"可能被问到的问题"，不是真题。

## 8. 下一步

- 扩充题库到 60 项 + 难度分层（一面/二面/HR 面）；
- 接"回答评分"：用规则（结构完整性/是否有数字）做第一版，不依赖模型；
- 和面试复盘器打通：真实面试题一键导入复盘器。
